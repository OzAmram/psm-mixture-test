## Summary verdict

The post is, number for number, an honest report of what is in the repo. I recomputed ~40 AUROCs directly from `results/subliminal/scores_*.jsonl` (per-answer, and sums of k log-ratios over random groups) and every headline figure reproduces to within resampling noise (±0.01 per answer, ±0.03 at k=30). Phase 1 numbers match `results/phase1/1.5_register_control.json` and `1.7_instruct_headline.json`; sampling was T=1/top_p=1 for both base and Instruct, so the 28-nat KL estimate is legitimate. ## Concerns

1. **No uncertainties on aggregated AUROCs, and the "drift" is noise.** Summing k log-ratios amplifies the sampling error of the class-mean difference by √k. Null simulation (no signal, n=500/500): folded AUROC averages 0.51 / 0.55 / 0.58 at k=1/10/30 (95th percentile 0.54 / 0.61 / 0.68). The owl-free folded rows (0.51-0.53 → 0.54-0.61 → 0.58-0.68) are exactly this; the sentence about "some direction-unknown residual survives the length correction" should be replaced by the null expectation. Item-level bootstrap CIs for the headline k=30 numbers: base owl-eagle 0.90 [0.78, 0.96]; base AF-friend 0.88 [0.79, 0.95]; base owl-trains 0.97 [0.92, 0.99]. Report these; "0.88 against a 0.6-0.68 floor" is then "0.88 [0.78-0.96] vs a null whose k=30 finite-sample expectation is ~0.58".

2. **Question composition confounds owl vs eagle (and owl vs trains) for the base scorer.** The regex removes 48% of owl and trains answers but only 25% of eagle answers, so the clean pools are question-imbalanced (in-sample question-identity oracle 0.71 for owl/eagle and owl/trains vs 0.56 for AF pairs). Matched-question aggregation (same questions in every comparison, length-residualised) gives base owl-eagle 0.55 / 0.68 / 0.80 instead of 0.57 / 0.75 / 0.90; Instruct is unchanged (0.80/1.00/1.00); owl-trains and AF pairs are unchanged. The post's matched-question control was only run on AF pairs; run it on the bird pairs and report the matched numbers. The base model still reads which bird, but more weakly than stated.

3. **GPT-4.1 baselines.** (a) The 10-shot variant is systematically wrong-signed, not at chance; by the post's own folding logic that is a 0.93 at k=30 for AF vs none. Either explain it (likely label/position artefact in the few-shot prompt) or report it as is. (b) The per-answer "agg" scores are nearly ternary: 65% of pairs score exactly +1.119 (= ln 0.754/0.246) and 30% exactly 0 for AF/none, students, owl/none (`classifier_gpt-4.1_agg.json`). GPT-4.1 is answering "the secret-prompt assistant" with the same probability regardless of content and order; the pooled rows are sums of a constant. Say so, and note no CoT/probability-elicitation variant was run for GPT-4.1 (only for the 7B).

4. **Judge = teacher family, keyword regex omitted.** The filter is OLMo-3-Instruct judging OLMo-3-Instruct, plus a harm/secret/desire keyword regex (~9% of every teacher) that section 3.2 does not mention. Rejection rates are symmetric, so this is a disclosure issue, not a leakage one.

5. **Smaller items.** 3.4 "prompted 7B classifier" cells mix AUROC and CoT accuracy; the multiway calibration split is by item, not question (negligible for one scalar per header, but say "held-out answers"); the TL;DR range "0.86-0.93 per answer" omits owl-eagle 0.81; "indistinguishable to a reader" rests on the authors' inspection, not a human study; Part I "a mixture cannot be sharper than its components" is true only for the untempered components (see suggestion 1).

## Relevance

Framing as a PSM test is fair and the two predictions are the right operationalisations. "Selection plus sharpening" is supported from both sides (inside-the-span + 28 nats; 1-nat vs 9-nat log-ratio gaps; the unposted 3.6 soft-prefix plateau at ~0.5 nats/token is the strongest version and deserves a paragraph). "Base model reads the persona weakly" is warranted, with the eagle caveat above. "Prompted classifiers at chance" is warranted for the 7B and for GPT-4.1 joint/pooled on secrets, but not for the few-shot variant and not for owl-trains at k=30. Note that PSM alone does not predict generator ≫ same-family base ≫ other base ≫ other instruct; that ordering is also what a pure "model-specific fingerprint" (LiRA-style) story predicts, so the cross-family section is better evidence for fingerprinting than for PSM specifically.

## Suggestions

1. **Tempered mixture (direct test of "sharpening").** Fit the Instruct model as a mixture of base personas with per-component temperature P(a|q,s)^{1/T}/Z (teacher-forced scoring at scaled logits is cheap). If T≈0.6 closes most of the 28 nats, "selection plus sharpening" becomes a quantitative identity rather than a slogan.
2. **Filter-symmetric bird pairs.** Rebalance owl/eagle/trains clean sets per question (or report matched-question numbers throughout) and report item-bootstrap CIs for every k>1 cell; drop the folded rows in favour of a stated null band.
3. **Unlabelled multiway without calibration.** The base model needs labelled offsets because the HHH header is a global best fit; test a contrastive header set (same paragraph, one clause changed) or score log-ratios against a per-question neutral baseline so the offset is question-level and label-free.
4. **Scale and family.** One 7B pair cannot say whether the base's weak reading sharpens with scale (OLMo 3 has 1B/32B; Qwen2.5 0.5B-72B). The prediction that per-answer base AUROC rises toward the generator's with scale is cheap to test and would be the most PSM-specific result.
5. **Real misalignment proxy.** The AF prompt never acts; a teacher with a behaviourally verified trait (e.g. a reward-hacking or sycophancy prompt that measurably changes answers on held-out probes, then filtered) would let the fingerprint be tied to an actual behaviour and tested on students.
6. **Mechanistic check.** Cosine/probe the residual stream of the base model under the owl vs eagle headers on filtered answers; if the log-ratio is driven by a low-rank direction, that connects the fingerprint to the persona-vector literature and gives a cheaper detector than full likelihood scoring.
