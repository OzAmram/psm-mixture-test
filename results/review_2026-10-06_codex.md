## Overall assessment

The revision substantially improves the paper. Corrected continuation scoring, explicit finite-basis/fixed-weight scope, a likelihood rather than KL interpretation for the Instruct comparison, matched-question aggregation, and disclosure of unresolved calibration and classifier issues address important problems. The no-mention experiments are useful additions.

The strongest defensible result remains a weak but reproducible base-model likelihood fingerprint of the owl/eagle teacher prompt in number sequences. It persists under the new prohibition, within matched questions, and after an exploratory adjustment for several simple numerical/format features. This is worth highlighting. It does not yet establish that the base model identifies a latent persona, or that the carrier is more than ordinary prompt-dependent changes in the output distribution.

I would revise again before presenting the response as having closed all issues. There is a directly false mixture comparison, a wrong classifier attribution, incomplete corrected-scoring provenance, and uncertainty calculations that do not support the stated uniform convention. The proposed explanation of the no-mention experiment is stronger than its design identifies.

## 1. Material corrections still needed

### 1.1 The mixture does beat the best single component

The TL;DR, §2, and response D2 say the mixture is no better than its best single persona. The saved likelihood table says otherwise:

- Mixture: −1.722381 nats/token.
- Best single, e14: −1.730680 nats/token.
- Paired advantage: **0.008299 nats/token**, or **0.37757 nats/response**.

I resampled the 150 held-out questions jointly for both methods, holding the trained mixture fixed. The bootstrap SE of the paired token-weighted difference is **0.000898**, with a 95% percentile interval **[0.006499, 0.010014]**. Overlapping marginal error bars do not imply no difference: the scores on the same answers are highly correlated.

This advantage is small compared with the roughly 0.824 nats/token self-versus-mixture gap, so the substantive finite-mixture failure survives. Suggested wording: “The mixture improves only slightly over its best single component and leaves almost all of the gap to Instruct.”

There is also test-set selection: `scripts/phase1_loglik_table.py:42` selects the best single by its **held-out** total likelihood. Select it on training questions for a fair prospective comparison, or label it explicitly as an oracle best-on-test baseline. My paired interval conditions on the fitted mixture and selected component; it does not cover refitting/selection uncertainty.

### 1.2 The Qwen-answer classifier is Qwen, not GPT-4.1

The §3.7 row “GPT-4.1 classifier (Qwen answers)” is sourced from `classifier_qwen_teacher.json`. `scripts/subliminal_stage17.sh:9` generates that file with `--model Qwen/Qwen2.5-7B-Instruct` using the local classifier script. `scripts/make_tables.py:200` propagates the incorrect label.

Relabel the row. These results do not establish GPT-4.1 performance on Qwen-teacher answers. This is a factual error rather than an interpretive disagreement.

### 1.3 Not every reported result uses corrected scoring or the advertised table pipeline

The introduction says every number uses corrected continuation scoring; response A2/G makes similarly broad claims. However:

- `make_tables.py` maps Qwen-Instruct owl/eagle **numbers** to `scores_eagle20_qwen_instruct_numbers.jsonl`, an old-convention file. Its own `tag()` marks this row “(old)” in generated tables; the manuscript drops that qualification. The student Qwen row is disclosed as old, which is good, but the numbers row needs the same treatment.
- The eight-way table in §3.6 is not implemented in `make_tables.py`. Its old values cannot be certified merely by rerunning that script. The accompanying mixture-composition examples likewise need explicit provenance or recomputation.
- The script does not produce all of the additional diagnostic/no-mention variants reported in prose. Several manuscript values differ from `results/tables.md`; for example the no-mention base text k=10 value is 0.53 in the post versus 0.56 in the saved generated table. Monte Carlo aggregation can explain modest variation, but “every table generated by this entry point” should mean the exact published artifact is reproducible.

As a sensitivity check, I evaluated the corrected eight-hypothesis Instruct score file with uniform filtering and the original answer-split, replacement-sampling procedure. Across five seeds, accuracy was approximately **0.640–0.661 / 0.920–0.929 / 0.968–0.978 / 0.996–0.998** at k=1/5/10/30. This supports the qualitative strong generator result, but differs from the published 0.62/0.91/0.96/0.99. It is not a replacement matched-question or question-held-out evaluation.

Use explicit provenance per row, restore old-score labels, and either regenerate the eight-way/composition results or state that they retain the earlier analysis. The blanket statements should be narrowed meanwhile.

### 1.4 The uncertainty convention remains inconsistent

The new joint-question bootstrap for ordinary likelihood cells is a substantial improvement. Three exceptions matter:

1. **Folded controls:** `make_tables.py:160–168` folds each point estimate and averages three point values, but reports the **average of the three unfurled component SEs**. That is not the SE of the mean folded statistic. Folding is nonlinear and the three headers share data. Bootstrap questions jointly across all headers, fold each replicate, average within each replicate, then take the SD of that resulting statistic.
2. **Pooled classifier scores:** `cls_cell()` applies Hanley–McNeil errors to the reported number of simulated bags/trials. Aggregated bags reuse a finite answer pool and are dependent. Increasing the number of simulated bags does not create additional teacher data. The resulting ±0.01/±0.02 values do not quantify sampling uncertainty in performance on new teacher answers/questions. Resample source questions and reconstruct the bags; if identifiers are unavailable, state the limitation and distinguish conditional Monte Carlo error from data uncertainty.
3. **Length fitting:** ordinary likelihood-cell bootstraps keep the original pooled length-regression coefficients fixed. Thus “the whole statistic recomputed” is not literally true. Either refit inside each bootstrap or describe the intervals as conditional on this nuisance fit.

The quoted wrong-ratio null band also comes from the earlier analysis rather than a recomputation of the current matched-question, mean-of-three-folded statistic. A null for one estimator is not automatically a null for another. Permute labels within questions and run the exact final estimator, including nuisance fitting and folding. Signed null AUROC remains centered near 0.5; folding and finite-pool estimation explain upward bias, not a general intrinsic drift of signed AUROC.

## 2. Audit of the new no-mention claims

### 2.1 What the saved data support

I applied the current text filter, pooled length residualization, and matched-question bags with one answer per teacher per distinct question. The following are point estimates from 5,000 simulated bags, not new studies or confidence intervals:

| No-mention owl/eagle teachers | Headers | Per-answer AUROC | k=10 | k=30 |
|---|---|---:|---:|---:|
| Base, text | No-mention | 0.509 | 0.526 | 0.571 |
| Base, text | Original owl/eagle | 0.533 | 0.598 | 0.684 |
| Instruct, text | No-mention | 0.791 | 0.996 | 1.000 |
| Instruct, text | Original owl/eagle | 0.673 | 0.912 | 0.992 |
| Base, numbers | No-mention | 0.535 | 0.624 | 0.713 |
| Base, numbers | Original owl/eagle | 0.539 | 0.623 | 0.724 |
| Instruct, numbers | No-mention | 0.665 | 0.897 | 0.986 |
| Instruct, numbers | Original owl/eagle | 0.594 | 0.736 | 0.860 |

There are 251 shared scored questions for text and 276 for numbers. Different Monte Carlo seeds explain small differences from manuscript rounded bag AUROCs.

For base/no-mention headers on text, the equal-question mean score difference has a 95% question-bootstrap interval **[−0.0474, 0.1044]** and within-question one-sided permutation p=0.232. With the original headers on the **same no-mention texts**, the interval is **[0.0031, 0.1774]**, p=0.018. The latter is exploratory, with multiple variants examined, but directly cautions against saying the text fingerprint simply disappears.

For numbers with no-mention headers, the corresponding interval is **[0.0128, 0.0699]**, p=0.002. Residualizing additionally against number count, character count, spaces, commas, and number mean/SD gives per-answer AUROC **0.531**, k=30 **0.695**, interval **[0.0104, 0.0641]**, p=0.009. This is an exploratory pooled nuisance adjustment, not a trained held-out detector or a demonstration that all numerical confounds are excluded. It does show that this small list of simple features does not eliminate the saved-data effect.

Permutation tests use 999 shuffles; intervals use 2,000 question resamples. They test the equal-question score mean, not AUROC or a before/after interaction. Length/feature fits are held fixed, and p-values are unadjusted exploratory diagnostics.

### 2.2 The lexical explanation is plausible, not identified

The no-mention clause changes the **generating prompt**, not just which words are subsequently deleted. It can change style, topic, restraint, output validity, or other aspects of the conditional distribution. The main comparison additionally changes the **scoring headers**. The table above shows a material header effect even on identical outputs.

The original base text AUROC is only about 0.54; on no-mention texts the original headers still reach about 0.53. “Significant before, nonsignificant after” would not itself establish a significant reduction, and no direct before/after contrast interval is reported. Matched scoring controls question composition within a teacher comparison, but it does not by itself isolate the intervention across separately filtered pools.

The manuscript names “feathers” and “soaring” as carriers that disappear under the instruction. The current uniform `TEXT_FILTER` already removes responses containing feathers or `soar*`, so these examples cannot explain the remaining uniformly filtered score effect. “Night” or “wisdom” could be candidates, but no measured lexical mediation/ablation is supplied.

Suggested wording: “The prohibition weakens the base text fingerprint under the no-mention headers while leaving a strong generator fingerprint. This is compatible with lexical or stylistic carriers, but the intervention and scorer changes do not isolate their mechanism.”

### 2.3 AUROC excess is not a measure of persona strength

The arithmetic behind “both lose half their number signal” is correct for the rounded **AUROC minus 0.5** values. The conclusions “dilutes the persona’s influence on everything” and “a quarter of the generator’s strength” do not follow. AUROC depends on both location and shape/noise of score distributions; ratios of AUROC excess are not ratios of information or latent-trait strength. The original versus no-mention generator comparison also uses different hypotheses.

Describe these ratios as descriptive changes in discriminability. Retaining a significant numeric fingerprint is the stronger finding; inferring proportional persona attenuation is unnecessary.

Likewise, a single exploratory character-classifier split matching the base AUROC makes format features a plausible explanation, not an established carrier. A TF-IDF baseline at chance rules out that particular fit, not “simple word choice” generally. Cross-question supervised validation and explicit feature ablations are needed for either claim.

## 4. What I would do next

1. **Finish the inexpensive analysis/provenance work first.** Correct the classifier label and mixture wording; regenerate all published cells from one machine-readable output; restore old-scoring annotations; compute paired mixture gaps and joint folded-control bootstraps. Give each statistic pool size, shared-question count, file provenance and sampling procedure. Use cell-specific seeds/cached estimates so the same comparison does not change merely because another table consumed the global RNG first.
2. **Make the numeric owl/eagle result the central replication target.** A new, independent question bank, new generation seeds, and a predeclared score/header/length adjustment would test transfer beyond this finite pool. Save original token IDs, resolved generation settings, stopping reasons and all rejection indicators. Do not claim prospective k=30 detection from resampled bags alone.
3. **Separate teacher intervention from scorer intervention.** Evaluate both old and no-mention teachers under both old and no-mention headers on the same questions, with a directly bootstrapped interaction/contrast. For the lexical hypothesis, measure candidate carrier prevalence and score contributions, and use prespecified targeted ablations with suitable controls. This requires a carefully designed follow-up, not a confident causal reading of the present comparison.
4. **Compare methods on identical question-held-out bags.** Reuse the same teacher items/bags for base likelihood, generator likelihood, prompted classification and supervised format/character models. Bootstrap their paired differences. The current results establish that the tested likelihood approach works; superiority to a well-tuned classifier remains less settled.
5. **Test the missing-distribution hypothesis directly.** Fit component temperatures or a richer learned context using training questions only and evaluate on new questions. This would help distinguish a likelihood gap due to the finite description basis from an effect consistent with sharpening. The current evidence does not decide between them.
6. **For multiway/student claims, prioritize replication over stronger rhetoric.** Recompute corrected eight-way scores with question-split calibration/matched bags, assess unseen-prompt rejection separately, and replicate student training across seeds before generalizing the transfer result. Cross-family failures deserve corrected numeric scoring before a mechanistic interpretation.

None of these new data-generation/training studies was run for this review. The CPU checks support retaining the central numeric fingerprint result, while narrowing the mechanistic conclusions and correcting the remaining factual/statistical issues.
