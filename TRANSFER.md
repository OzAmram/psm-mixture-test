# Moving this project to another cluster

Written 2026-11-02, when the project left NERSC Perlmutter. Steps in order; each one says how to check it worked.

## 1. Copy the repository folder (about 4.4 GB)

Copy the whole folder, not just a `git clone`: most results are gitignored.

```
rsync -a --exclude __pycache__ --exclude .ipynb_checkpoints \
    perlmutter:/global/u1/o/ozamram/personal/persona_selection_study/  NEW:/path/to/persona_selection_study/
```

What only the copy carries (not in git):

| folder | size | contents |
|---|---|---|
| `results/` | 4.1 GB | every fit, score matrix, self score, framing score, and the trained soft-context vectors (`prefix.pt`). 3.5 GB of it is `results/subliminal/` |
| `data/` | 275 MB | sampled answers and score matrices (questions and prompt files are also in git) |
| `logs/` | 5 MB | job logs that NOTES.md cites |
| root | small | `persona_geom_mixture.md`, `2609.16927v1.pdf`, uncommitted edits to `my_writeup_persona_mixture.md` |

Check: `git status` in the copy shows the same state as here, and `git log -1` is the latest pushed commit.

**Do not copy** `$SCRATCH/persona_phase4/hidden` (2.9 TB of base-model hidden states). Each set is regenerated by `scripts/phase4_hidden_states.py` in 1-2 h on 4 GPUs; the fits that need them say which (NOTES.md).

## 2. Edit `env.sh`

All cluster-specific settings are in one marked block at the top:

- `ENV_BIN`: the `bin` folder of the Python environment from step 3.
- `HF_HOME`: a persistent folder with room for about 200 GB of model weights.
- `SCRATCH`: a large folder for hidden states (several TB if Experiment 2 is rerun in full).
- `HF_HUB_OFFLINE=1`: keep. Downloads switch it off themselves.

Check: `source env.sh` prints the new python and `HF_HOME`.

## 3. Rebuild the Python environment

Python 3.11.15. `transfer/requirements-freeze.txt` is the exact package list (`pip freeze`, 2026-11-02). Key versions: torch 2.5.1 (CUDA 12.1 build), transformers 5.17.0, huggingface_hub 1.32.0, numpy 2.4.6, scipy 1.17.1.

```
conda create -p /path/to/envs/ml python=3.11.15
/path/to/envs/ml/bin/pip install -r transfer/requirements-freeze.txt --extra-index-url https://download.pytorch.org/whl/cu121
/path/to/envs/ml/bin/pip install -e .
```

The NERSC environment was shared with other projects, so the list has some packages this project does not use. If a few fail to install, drop them, but keep torch and transformers at these exact versions: other versions can shift log-likelihoods slightly, so old and new numbers would no longer be exactly comparable. If the new GPUs need a newer CUDA build of torch, record that in NOTES.md and rerun one reference number (step 6) to measure the difference.

## 4. Download the models (about 200 GB)

```
source env.sh
HF_HUB_OFFLINE=0 hf auth login        # Llama is gated: the account must have accepted Meta's Llama 3.1 license
bash transfer/download_models.sh
```

`transfer/model_revisions.txt` lists the exact snapshots every result used. The script downloads each by branch name and checks the branch still points to that snapshot (prints `MISMATCH` otherwise). It then checks that every model loads offline with complete weights (`OFFLINE FAIL` otherwise). Olmo-3-7B-Instruct needs four branches (`main`, `step_100`, `step_200`, `step_300`).

The Llama weights never arrived on NERSC (my download left the shards outside the cache), so Llama starts from scratch here.

## 5. Adapt the batch scripts

14 scripts in `scripts/` have Slurm headers for Perlmutter:

```
#SBATCH -A m2612_g -C gpu&hbm80g -q regular -N 1 -G 4 -c 128 -t 5:00:00
```

On the new cluster, change the account (`-A`), the GPU constraint (`-C`) and the queue (`-q`), or pass them on the `sbatch` command line. The code assumes:

- one 80 GB GPU per process;
- 4 GPUs per node for the parallel steps (`CUDA_VISIBLE_DEVICES=0..3`).

On 40 GB GPUs, the large geometric fits (`phase4_geom_fit.py`) will not fit as they are. Jobs must stay at or under 6 h.

Interactive allocations were used as `salloc ... --no-shell` plus `srun --jobid=<id> --overlap` (NOTES.md); the equivalent on the new scheduler may differ.

Notebooks: 14 notebooks contain NERSC paths, mostly in saved outputs. They read results from `results/` by relative path, so they should run once `env.sh` is set; any absolute path that fails is a one-line fix.

## 6. Check the new setup reproduces an old number

Before running anything new, on one GPU:

```
source env.sh
python scripts/phase4_self_tokens.py --run instruct_unknown_casual_v1 --model allenai/Olmo-3-7B-Instruct --tag check_newcluster
```

Expected: `self log P/token -0.8937` over all 2,400 answers (to about 0.001; bf16 kernels differ between GPU types; the -0.898 quoted elsewhere is the hold-out half). Compare it with the saved `results/phase4/self_tokens/instruct_unknown_casual_v1.npz` and delete the `check_newcluster` file afterwards.
